# Sabik · contexto histórico de proveedor IA

Fecha: 30/09/2026
Autoridad de contexto: María

## Decisión histórica

María explica que, cuando conectó NEA —hoy Sabik—, eligió Claude como proveedor de IA porque en ese momento OpenAI no ofrecía para el proyecto la API/capacidades que ella necesitaba.

La conexión con Claude fue por tanto una decisión técnica contextual, no un error que deba “deshacerse”.

## Situación actual

El ecosistema de APIs ha cambiado y ahora se abre una nueva evaluación:

`CLAUDE ACTUAL → ESTUDIO OPENAI → EVALS → DECISIÓN → MIGRACIÓN CONTROLADA SI PROCEDE`

Córtex/A10 debe:
- documentar exactamente qué contrato/provider usa Sabik hoy;
- identificar qué capacidades motivaron la arquitectura original;
- comparar con las capacidades OpenAI vigentes;
- evitar reescribir Sabik por cambiar de proveedor;
- preservar rollback.

No se registra como hecho universal que OpenAI “no tuviera ninguna API” en términos históricos generales; se conserva la razón aportada por María en el contexto concreto de NEA/Sabik y sus necesidades de entonces.
